# Resume PDF Generation

## Library: @react-pdf/renderer v4

- NPM: `@react-pdf/renderer` (v4.5.1 as of July 2026)
- Repo: `/diegomura/react-pdf`
- Docs: `https://react-pdf.org/`
- API docs: `https://context7.com/diegomura/react-pdf/llms.txt`

## Cloudflare Workers Compatibility

**Status: works with bundler alias.** No native Workers support.

### The issue

`@react-pdf/layout` imports `yoga-layout` which loads a WASM binary. Cloudflare Workers blocks dynamic WASM code generation with `"Wasm code generation disallowed by embedder"`.

GitHub issue: https://github.com/diegomura/react-pdf/issues/2757

### The fix

Patch `@react-pdf/layout` to use `yoga-layout/asmjs-sync` (ASM.js fallback, no WASM). In a Vite/TanStack Start project, this can be done in `vite.config.ts`:

```ts
resolve: {
  alias: {
    "yoga-layout": "yoga-layout/asmjs-sync"
  }
}
```

Or via a `patch-package` patch on `@react-pdf/layout` to change its import from `yoga-layout` to `yoga-layout/asmjs-sync`.

This is a well-documented, single-line alias — not a deep fork. React-pdf has had this issue open since May 2024 with the ASM.js workaround confirmed by multiple users.

### Server-side API

Use `renderToBuffer` — renders a React element tree to a `Uint8Array` (Node.js Buffer). Works in Workers with `nodejs_compat` flag (already set in `wrangler.jsonc`).

```tsx
import { renderToBuffer } from "@react-pdf/renderer";

const buffer = await renderToBuffer(<ResumeDocument data={data} />);
// buffer is Uint8Array, uploadable to R2
```

### Font loading

`Font.register` accepts URLs (HTTP/HTTPS) for font files. On Workers, fetch fonts from a CDN or bundle them as assets:

```tsx
import { Font } from "@react-pdf/renderer";

Font.register({
  family: "Inter",
  src: "https://fonts.gstatic.com/.../Inter-Regular.ttf"
});
```

Font registration must happen once at module scope, before rendering.

## ATS-Compatible PDF Guidelines

Generated by @react-pdf/renderer renders as real text (selectable, searchable) — not rasterized. This is inherently ATS-friendly.

### DOs

- **Use `Text` component** for all text content (never embed text in images)
- **Single-column layout** — no multi-column sections (ATS reads left-to-right, top-to-bottom)
- **Standard fonts** — register standard system fonts (Inter, Roboto, Open Sans, Noto Sans) from a CDN URL
- **Bullet points** — use plain text characters (`•`, `-`) in `Text`, not `View`-based bullet decorations
- **Simple tables** — use `View` with `flexDirection: "row"` for horizontal layout, not actual PDF tables
- **`View` for layout** — use `View` with `flexDirection: "column"` / `"row"` for structure
- **Header/footer** — use `position: "absolute"` with `fixed` prop for page numbers
- **`Link` component** — for URLs (ATS reads them as text)
- **PDF metadata** — set title, author on `Document` component for document properties

### DON'Ts

- No images for text content (ATS can't read text in images)
- No graphics/icons/logos unless decorative (ATS ignores images)
- No header/footer with complex formatting in the margins (some ATS miss text in page headers/footers)
- No text boxes or floating elements (use `View` with proper flex layout instead)
- No colors that reduce contrast (ATS reads text regardless, but humans still review)

### Section structure (standard order)

1. **Header** — Name (large bold), contact info (small, single line)
2. **Summary** — prose paragraph (dropped for MVP)
3. **Experience** — company, title, dates, bullet points
4. **Projects** — title, tech, description
5. **Skills** — categorized lists
6. **Education** — degree, school, dates (dropped for MVP)

### Text styling for ATS

```tsx
<Text style={{ fontSize: 11, lineHeight: 1.4, fontFamily: "Inter" }}>Bullet point text here</Text>
```

Use standard sizes:

- Name: `fontSize: 20-24`
- Section headers: `fontSize: 12-14, fontWeight: "bold", uppercase, letterSpacing: 1-2`
- Body text: `fontSize: 10-11`
- Dates: `fontSize: 10`

## Generate Flow (Server Function)

```
[Dashboard "Generate" button]
         ↓
  Server function (TanStack Start server function)
         ↓
  Fetch portfolio data (portfolio.list)
  Fetch profile (profile.get)
         ↓
  Render PDF via renderToBuffer(<ResumeDocument data={...} />)
         ↓
  Upload buffer to R2 (MEDIA_BUCKET) via files-sdk or direct put()
         ↓
  Insert resume row in DB (id, prompt, author, filename, r2Key, default)
         ↓
  Return resume ID to client
```

## Delete Flow

```
[Dashboard delete button]
         ↓
  Delete object from R2 (using r2Key)
  Delete resume row from DB
         ↓
  Invalidate queries
```
