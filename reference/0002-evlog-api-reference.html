evlog & @tsu-stack/logger — API Reference

evlog v2.18 · The "wide event" logger powering this monorepo. Print-friendly.

Logger Types

evlog provides three families of logger. Know which one you need:

Type Import Scope Need .emit()? Use case
RequestLogger @tsu-stack/logger/server One HTTP request Yes (auto by middleware) oRPC procedure handlers, route handlers
Standalone Logger @tsu-stack/logger/server One job / script call Yes (you call it) Cron jobs, background tasks, getRepoOverview
Global log @tsu-stack/logger/server Application-wide singleton No (auto-flush) One-off events, startup logs, error pages

RequestLogger API

Request-scoped wide-event logger. Created by Hono/TanStack Start middleware. Available as context.logger in oRPC procedures.

Method Signature Description
.set() set(ctx: object): void Merge context into the wide event (deep merge). Arrays concatenate.
.info() info(msg: string, ctx?: object): void Add an info-level request log entry (sub-event in the wide event's requestLogs[]).
.warn() warn(msg: string, ctx?: object): void Add a warning-level request log entry.
.error() error(err: Error | string, ctx?: object): void Record an error on this request. Sets level: "error" automatically.
.emit() emit(overrides?: object): WideEvent | null Flush the wide event to drains. Seals the logger — no more mutations allowed. Returns null if sampled out.
.setLevel() setLevel(level: LogLevel): void Manually override the log level (overrides auto-detection from .error()).
.getContext() getContext(): object Read back all accumulated context so far (useful for debugging).
.fork() fork(label: string, fn: () => void): void Run background work in a child wide event with operation and _parentRequestId set. Child emits when fn settles.
.audit() audit(input: AuditInput): void Record a structured audit event. Includes .deny(reason, fields) sub-method for AuthZ denials.
Key constraint
After .emit() is called, the logger is sealed. Subsequent .set(), .info(), .warn(), .error() calls log a console warning and are ignored. A second .emit() is also a no-op.

Standalone Logger API (createLogger)

Not attached to any request. Caller must .emit() manually.

Method Description
createLogger({ source: "..." }) Create a new standalone logger. Pass source to identify the caller.
.set({ key: val }) Accumulate structured context (same deep merge as RequestLogger).
.emit({ status?, ... }) Flush and seal. Without this, the event is silently dropped.
.info() / .warn() / .error() Same as RequestLogger — add sub-events (stored in requestLogs[]). 
import { createLogger } from "@tsu-stack/logger/server";

const logger = createLogger({ source: "github.repo.getRepoOverview" });
logger.set({ owner, repo, handler: "getRepoOverview" });
logger.emit({ status: 200 });  // ← Without this line, nothing happens!

Global log API

Singleton facade — fire and forget. No .emit() needed. Two call signatures: 

// Object form (wide event — preferred for structured data)
import { log } from "@tsu-stack/logger/server";
log.info({ event: "server_started", port: 5000 });
log.error({ event: "rpc_error", handler: "health.live", error: err.message });

// Tag + message form
log.info("auth", "User logged in");
log.error("payment", "Payment declined");
Method Level
log.debug() Debug
log.info() Info
log.warn() Warning
log.error() Error
When to use global log vs RequestLogger
Use context.logger (RequestLogger) inside oRPC handlers — it auto-correlates with the HTTP request (method, path, requestId, duration, status).
Use log for one-off events that aren't part of a request (server startup, cron tick, health check results from a non-request context).
Use createLogger for self-contained multi-step work like getRepoOverview that needs its own structured event.

Wide Event Structure

Every emitted event has this base shape + your custom context:

{
  timestamp: "2026-06-10T12:00:00.000Z",
  level: "info",
  service: "server",
  environment: "production",
  version: "abc123",
  duration: 342,           // auto-tracked (request loggers)
  status: 200,
  method: "GET",
  path: "/rpc/github/repo/overview",
  requestId: "a1b2c3d4-...",
  ip: "203.0.113.42",
  hostname: "api.example.com",

  // Your context via .set():
  owner: "salah",
  repo: "portfolio-v2",
  handler: "rpc",

  // Sub-events from .info() / .warn() / .error():
  requestLogs: [
    { level: "info", message: "Cache HIT", timestamp: "..." }
  ],

  // Only when log.audit() is used:
  audit: { action: "invoice.refund", actor: { ... }, outcome: "success" }
}

Hono Middleware Flow

How context.logger reaches your oRPC handler:

Flow
1. HTTP request arrives at Hono server
2. honoLoggerMiddleware() fires on "/*"
   → creates RequestLogger, stores as c.get("log")
   → starts duration timer
3. Router matches route
4. createContext({ context: c, logger: c.get("log") })
   → returns { github, session, logger }
5. rpcHandler.handle(request, { context })
   → dispatches to matching procedure
6. Your handler gets context.logger
   → call .set(), .info(), .error() as needed
7. oRPC error interceptor fires on throw
   → context.logger.set({ handler: "rpc" })
   → context.logger.error(error)
8. Hono response sent
9. evlog middleware auto-calls .emit() ← SEALS
   → wide event goes to drains (console, Axiom, etc.)

@tsu-stack/logger Re-exports

The thin facade:

Export Source Description
initLogger() evlog Initialize once per process. Sets env, redact, sampling.
createLogger() evlog Standalone wide-event logger. Caller must .emit().
createRequestLogger() evlog Request-scoped logger (manual — not from middleware).
log evlog Global singleton facade. Auto-flush, no .emit() needed.
createError() evlog Structured error factory: { message, status, why, fix, code }.
parseError() evlog Convert unknown errors into safe response objects.
LOG_SERVICES — Enum: DEFAULT, SERVER, WEB_CLIENT, WEB_SERVER
RequestLogger (type) evlog Type for the request-scoped logger.
ParsedError (type) evlog Type for parsed error output.

Log Levels & Sampling

Level Priority Default sample
error 4 (highest) 100%
warn 3 100%
info 2 100% (can be lowered via sampling.rates.info)
debug 1 (lowest) 100%

Tail sampling (sampling.keep) can force-keep events by status, duration, or path glob. See apps/web/src/start.ts for an example that keeps all 400+ responses and requests > 1000ms.

Anti-patterns (Current Code Issues)

Bug: standalone logger without .emit()

packages/github/src/repo/get-repo-overview.ts:16-30

const logger = createLogger({ source: "github.repo.getRepoOverview" });
// ...
logger.set({ handler: "getRepoOverview" });
logger.set("GitHub source...", { reason: source.reason });
// 🚫 Never calls .emit() — event is silently dropped!

The context is accumulated but never flushed to drains. Fix: add logger.emit() after the last .set() call.

Missed opportunity: context.logger unused in procedures

All Router files in packages/api/src/routers/

Every oRPC handler receives context.logger (RequestLogger), but none use it. The only procedure that logs (health.live) uses the global log.info() instead, which doesn't correlate with the request's method, path, or duration.
