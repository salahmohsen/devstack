@tsu-stack/github — Glossary & Reference

Key terms, types, files, and patterns in the GitHub integration. Print-friendly.

Core Types

GitHubLocalFirstResult<T>
packages/github/src/types.ts:226
Wrapper returned by all cache-aware fetchers. Contains data: T and meta: GitHubLocalFirstMeta (which has fresh, miss, stale status).
GitHubRuntimeBindings
packages/github/src/runtime/bindings.ts:28
Union type for Cloudflare-specific runtime features: executionContext (waitUntil), kv (cache KV), signalRelay (DO stub). All are optional, making the core package runtime-agnostic.
GitHubResponseMetadata
packages/github/src/infrastructure/octokit/client.ts:10
Extracted response metadata: etag, lastModified, rateLimitRemaining, rateLimitReset, statusCode. Used by the cache layer for conditional requests.
PublicGitHubSource
packages/github/src/shared/public-github-source.ts:3
Discriminated union: { isConfigured: false, reason } or { isConfigured: true, owner, token }. Resolved from DB app settings.
CachedGitHubEntry<T>
packages/github/src/infrastructure/cache/github-cache.ts:34
Shape of a cached response: etag, fetchedAt, lastModified, staleAt, namespaceVersion, payload.

Key Functions

getGitHubResourceLocalFirst
packages/github/src/infrastructure/cache/github-cache.ts:74
The central cache orchestrator. Every GitHub data function calls this. Flow: check KV → check DB → if fresh, return → if stale, fetch with conditional headers (ETag/If-None-Match) → on 304, extend staleAt → on 200, update cache → on 403/429, return stale data.
createGitHubOctokit
packages/github/src/infrastructure/octokit/client.ts:18
Factory that creates an Octokit instance with the configured token. All REST and GraphQL calls go through this.
handleGitHubWebhook
packages/github/src/webhooks/handle-github-webhook.ts:24
Main webhook entry point: verifies HMAC-SHA256 signature, records delivery in DB, computes revalidation signal keys from event type, marks signals and bumps cache namespaces, broadcasts to DO if signalRelay is available.
bumpGitHubCacheNamespaces
packages/github/src/infrastructure/cache/github-cache.ts:46
Increments namespace version counters in DB. Stale entries with a lower namespaceVersion than current will be considered stale on next read.
markGitHubRevalidationSignals
packages/github/src/infrastructure/cache/github-cache.ts:53
Sets signal key → timestamp pairs in DB. On cache read, if signal timestamp is newer than the entry's fetchedAt, the entry is considered stale.

Cache Policy Categories

staleTimeMs
How long data is considered fresh. After this, the entry is stale but still returned while a background revalidation is triggered.
gcTimeMs
How long stale entries are kept before garbage collection. Data older than this is considered "miss" and must be re-fetched.

Revalidation Signal Keys

githubRevalidationSignalKeys = {
  ownerActivity(owner)         // "ownerActivity:{owner}"
  ownerContributions(owner)    // "ownerContributions:{owner}"
  ownerPinnedRepos(owner)      // "ownerPinnedRepos:{owner}"
  ownerProfile(owner)          // "ownerProfile:{owner}"
  ownerRepos(owner)            // "ownerRepos:{owner}"
  repoCode({ owner, repo })    // "repoCode:{owner}/{repo}"
  repoMeta({ owner, repo })    // "repoMeta:{owner}/{repo}"
}

On the client side (src/lib/github-revalidation.ts), a broader set includes pullsMine, issuesMine, notifications, repoLabels, and more.
